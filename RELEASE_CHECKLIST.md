# Solace Android release checklist

1. Keep a JSON backup from the installed phone outside the app. If its old version cannot download one, use the same Chrome remote DevTools console backup that previously reported "Backup copied to clipboard," paste the JSON into Notepad, and save it as a `.json` file on the PC. Verify the record counts before installing anything. Keep another private copy. The previous snapshot contained 6 students, 340 classes, 28 payments, 11 test results, 7 parent contacts, and 25 communications; current phone counts may be higher.
2. Configure and start the authentication server with a private secret and a persistent SQLite database. Run migrations and create the initial tutor account once. Point `VITE_API_URL` and `BETTER_AUTH_URL` at its HTTPS address, allow the Android origin `https://localhost`, and check that the server is reachable from the phone.
3. Run `npm ci`, `npm test`, `npm run build`, and `npx cap sync android` from `Mobileapp/`.
4. Open `android/` in Android Studio. Set **Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK** to JDK 17 or 21, then wait for Gradle sync. The Android Gradle plugin is 8.13.1 and the wrapper uses Gradle 8.13. Gradle 8.13 cannot run on JDK 25; do not accept an automatic jump to Gradle 9.x without testing compatibility.
5. The project now uses Android `versionCode` 4 and `versionName` 1.3. Keep the application ID `com.tutortrack.app` so Android recognizes the update.
6. Sign the APK with **the same certificate** used by the currently installed app. Keep the signing keystore and its passwords backed up privately; do not commit them to Git. A debug APK can update another debug APK only when its debug certificate matches. An APK signed with a different certificate cannot update in place.
7. Install over the current app using Android Studio **Run** or `adb install -r path/to/app.apk`. Never uninstall the old app to fix a signature error. Stop and compare certificates instead.
8. Sign in as tutor on the phone. If the hosted server is empty, the app imports existing device records automatically. If the server has different records, the app stops and displays both sets of counts; save a device backup and choose **Use this device’s records on the server** only after reviewing them. Verify counts before inviting students. Create a new JSON backup from the updated app and back up the SQLite database.
9. Invite a test student, then check messaging, announcements, homework downloads, and a scheduled class reminder on two devices. The server must remain running; reminders appear inside the app and do not send push notifications.

The JSON backup contains names, phone numbers, and message history. Store it privately. The CSV statement contains student account details.
