# Solace Android release checklist

1. Keep a JSON backup from the installed phone outside the app. If its old version cannot download one, use the same Chrome remote DevTools console backup that previously reported "Backup copied to clipboard," paste the JSON into Notepad, and save it as a `.json` file on the PC. Verify the record counts before installing anything. Keep another private copy. The previous snapshot contained 6 students, 340 classes, 28 payments, 11 test results, 7 parent contacts, and 25 communications; current phone counts may be higher.
2. Before deploying version 2.0, save a verified full server snapshot with `npm run backup:server` and keep the phone JSON backup. Keep the existing Neon `DATABASE_URL`, `BETTER_AUTH_SECRET`, and URL/origin settings in Render. Deploy the server and verify the log says `Neon snapshot loaded at revision ...`. The startup migration assigns existing students, announcements, and homework to the original tutor without changing their IDs. For a brand-new server only, run the one-time `npm run setup:tutor` process before the first deployment.
3. Run `npm ci`, `npm test`, `npm run build`, and `npx cap sync android` from `Mobileapp/`.
4. Open `android/` in Android Studio. Set **Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK** to JDK 17 or 21, then wait for Gradle sync. The Android Gradle plugin is 8.13.1 and the wrapper uses Gradle 8.13. Gradle 8.13 cannot run on JDK 25; do not accept an automatic jump to Gradle 9.x without testing compatibility.
5. The project now uses Android `versionCode` 11 and `versionName` 2.0. Keep the application ID `com.tutortrack.app` so Android recognizes the update.
6. Sign the APK with **the same certificate** used by the currently installed app. Keep the signing keystore and its passwords backed up privately; do not commit them to Git. A debug APK can update another debug APK only when its debug certificate matches. An APK signed with a different certificate cannot update in place.
7. Install over the current app using Android Studio **Run** or `adb install -r path/to/app.apk`. Never uninstall the old app to fix a signature error. Stop and compare certificates instead.
8. Sign in as tutor on the phone. If this device has records but its owner is unknown or differs from the signed-in tutor, the app stops and displays both sets of counts. Save a device backup and choose which records to use only after reviewing them. If records match the server, they load normally. Verify counts before inviting students. Create a new JSON backup from the updated app and back up the server snapshot.
9. Invite a second teacher from Settings. That teacher should see only their own students. Invite an existing student email from the second teacher account and have the student accept the link using their existing login. Check the combined student dashboard, teacher filter, messages, announcements, homework downloads, and a scheduled class on two devices. Render Free sleeps while idle; its in-process reminder timer pauses during sleep, so timed reminders are not guaranteed. Reminders appear inside the app and do not send push notifications.

The JSON backup contains names, phone numbers, and message history. Store it privately. The CSV statement contains student account details.
